## Вывод об условии встраивании функций в LLVM:

1. Ключевое слово inline — это не приказ. Для LLVM (как и для других современных компиляторов) обычный inline в C++ является лишь рекомендацией. При -O0 компилятор игнорирует эту рекомендацию.
2. При O2 функция встраивается в main().
3. Атрибут __attribute__((always_inline)) заставит LLVM встроить функцию даже при -O0.

## Локальная оптимизация:
Удаление лишних скобок, если скобки не влияют на порядок операций
Удаление неиспользуемого параметра, если параметр объявлен в def, но не используется в return

Тестовый пример:
```
def multiply(x: int, y: int, z: int, m: int) -> int:
    return (x * y) + z;
```

## Ответы на контрольные вопросы

1. Clang — это фронтенд-компилятор для C-подобных языков, входящий в инфраструктуру LLVM. Его главная роль заключается в лексическом, синтаксическом и семантическом анализе исходного кода, проверке на ошибки и последующей трансляции этого кода в промежуточное представление (LLVM IR), которое затем передается бэкенду для оптимизации и генерации машинного кода.
2. LLVM — это фреймворк и набор модульных технологий для создания компиляторов и утилит анализа кода. В современных компиляторах он выполняет роль универсального бэкенда: принимает промежуточное представление (IR) от различных фронтендов, применяет к нему множество платформонезависимых оптимизаций, а затем генерирует высокоэффективный машинный код для конкретной целевой архитектуры процессора.
3. Абстрактное синтаксическое дерево отражает иерархическую, грамматическую структуру исходного кода и сильно привязано к синтаксису конкретного языка программирования. В отличие от него, LLVM IR — это плоское, низкоуровневое промежуточное представление, которое не зависит от исходного языка и оперирует базовыми блоками, инструкциями переходов и виртуальными регистрами, что делает его удобным для машинного анализа.
4. Промежуточное представление (IR) служит универсальным «языком-посредником» между фронтендом и бэкендом. Благодаря IR разработчикам не нужно писать отдельный компилятор для каждой пары «язык — архитектура процессора»; вместо этого все языки транслируются в единый IR, для которого один раз пишутся мощные алгоритмы оптимизации, применимые ко всем поддерживаемым языкам и платформам.
5. Инструкция alloca в LLVM IR предназначена для динамического выделения памяти на стеке вызовов текущей выполняемой функции. Она возвращает указатель на выделенную область памяти, которая автоматически освобождается при завершении работы функции (инструкция ret), и используется компилятором при отключенных оптимизациях для размещения локальных переменных до того, как оптимизатор попытается перенести их в виртуальные регистры.
6. Оптимизация кода необходима для преобразования программы в более эффективную форму без изменения её поведения. Основные цели оптимизации включают максимальное увеличение скорости выполнения программы (за счет сокращения числа инструкций, инлайнинга, векторизации), уменьшение объема потребляемой оперативной памяти, минимизацию размера итогового бинарного файла и, как следствие, снижение энергопотребления устройства.
7. Форма единичного статического присваивания (SSA) — это свойство промежуточного представления, при котором каждой переменной значение присваивается ровно один раз за всё время её существования в коде. Эта форма критически важна для оптимизаций, так как она явно связывает место определения значения с местами его использования, что радикально упрощает и ускоряет алгоритмы удаления мертвого кода, распространения констант и поиска общих подвыражений.
8. Граф потока управления (CFG) — это ориентированный граф, в котором узлами выступают базовые блоки, а ребрами — возможные переходы между ними. CFG позволяет компилятору математически точно анализировать все возможные пути выполнения программы, что необходимо для обнаружения недостижимого кода, оптимизации циклов и правильного распределения регистров процессора.
9. Арифметические операции в LLVM IR (такие как add, sub, mul) представлены в виде строгих, типизированных трехадресных инструкций, которые принимают два операнда одинакового типа и возвращают результат. В соответствии с правилами SSA-формы, результат любой арифметической операции всегда записывается в новый, уникальный виртуальный регистр, который затем может использоваться в последующих инструкциях.
10. Функции в LLVM IR выступают естественными границами для изоляции логики, имея четко определенные входы (аргументы) и выходы (возвращаемые значения), что делает их идеальными независимыми единицами для анализа. Оптимизация на уровне отдельных функций позволяет компилятору избегать экспоненциального роста сложности вычислений и чрезмерного потребления оперативной памяти, которые неизбежно возникли бы при попытке анализировать всю программу целиком как единый монолит.
11. Если функция очень короткая и/или вызывается всего один раз, при включенных оптимизациях специальный проход компилятора (Inliner) с высокой вероятностью выполнит её встраивание (инлайнинг). В этом случае инструкция вызова (call) удаляется, а тело короткой функции копируется непосредственно в место вызова, что полностью устраняет накладные расходы на вызов и открывает возможности для дополнительных оптимизаций.
12. Анализ IR и CFG дает колоссальное преимущество, поскольку они очищены от «синтаксического сахара» и сложностей исходного языка, сводя всю логику к  набору простых инструкций и явных переходов. Это позволяет применять к коду строгие математические алгоритмы и теорию графов, делая автоматические оптимизации надежными, быстрыми и независимыми от особенностей синтаксиса конкретного языка программирования.

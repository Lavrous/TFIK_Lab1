## Разработка грамматики
На основе реализованного парсера составлена следующая контекстно-свободная грамматика в классической форме Бэкуса-Наура (БНФ). 

```bnf
<Start>   ::= def <id> ( <Params> ) -> int : <Body>
<Params>  ::= <Param> <Params'> | ε
<Params'> ::= , <Param> <Params'> | ε
<Param>   ::= <id> : int
<Body>    ::= return <Expr> ;
<Expr>    ::= <Term> <Expr'>
<Expr'>   ::= + <Term> <Expr'> | ε
<Term>    ::= <Factor> <Term'>
<Term'>   ::= * <Factor> <Term'> | ε
<Factor>  ::= <id> | ( <Expr> )
<id>      ::= <Letter> <IdTail> | "_" <IdTail>
<IdTail>  ::= <Letter> <IdTail> | <Digit> <IdTail> | "_" <IdTail> | ε
```

Где базовые символы (терминалы лексического уровня) определяются следующим образом:
* `letter -> a | b | ... | z | A | B | ... | Z`
* `digit -> 0 | 1 | ... | 9`

**Формальное определение грамматики:**
Следуя формальному определению, представим грамматику как четверку $G = (V_N, V_T, P, Z)$, где её составляющие:

* **Z** — Целевой нетерминал (аксиома):
  `Z = <Start>`

* **Vt** — Множество терминальных символов:
  `Vt = { def, return, int, a, b, ..., z, A, B, ..., Z, 0, 1, ..., 9, (, ), ->, :, ,, ;, +, *, _ }`

* **Vn** — Множество нетерминальных символов:
  `Vn = { <Start>, <Params>, <Params'>, <Param>, <Body>, <Expr>, <Expr'>, <Term>, <Term'>, <Factor>, <id>, <id_tail> }`

## Классификация грамматики
Согласно иерархии Хомского, данная грамматика относится к **Типу 2 (Контекстно-свободные грамматики)**. 
Правила вывода имеют вид $A \rightarrow \alpha$, где $A$ — одиночный нетерминал, а $\alpha$ — цепочка терминалов и нетерминалов.

## Диагностика и нейтрализация синтаксических ошибок

В разработанном синтаксическом анализаторе используется стратегия восстановления после ошибок, основанная на **методе Айронса**.

### Суть метода

Суть метода заключается в том, что при обнаружении синтаксической ошибки анализатор не прекращает работу, а пытается восстановить свое состояние, чтобы продолжить анализ. Для этого он пропускает (игнорирует) входные лексемы до тех пор, пока не встретит один из заранее определенных **синхронизирующих символов** — лексему, которая с высокой вероятностью обозначает начало следующей синтаксической конструкции. Это позволяет выявить несколько ошибок за один проход.

### Реализация в работе

Каждая процедура разбора (`parse_Start`, `parse_Param`, `parse_Body` и т.д.) при обнаружении несоответствия текущей лексемы ожидаемой выполняет следующие шаги:
1.  **Формируется ошибка:** Вызывается метод `add_error()`, который сохраняет информацию о типе ошибки, ее местоположении (строка, позиция) и проблемной лексеме.
2.  **Ошибка заносится в таблицу:** Список ошибок пополняется для последующего вывода в интерфейсе.
3.  **Выполняется синхронизация:** Анализатор входит в цикл, в котором пропускает лексемы (`self.advance()`).
4.  **Поиск точки восстановления:** Пропуск продолжается до тех пор, пока не будет найдена лексема из "безопасного" набора для *текущего контекста*.

**Примеры контекстной синхронизации в коде:**

*   **При ошибке в параметре (`sync_param`)**: Если парсер не находит `:` или `int` в объявлении параметра (например, `a int`), он пропускает все лексемы до тех пор, пока не встретит запятую `,` (начало следующего параметра) или закрывающую скобку `)` (конец списка параметров).
*   **При отсутствии `return` (`parse_Body`)**: Если в теле функции отсутствует ключевое слово `return`, парсер пропускает токены до тех пор, пока не найдет лексему, которая может начать математическое выражение, — идентификатор (`id`) или открывающую скобку `(`.

### Алгоритм нейтрализации

Для каждой ошибки алгоритм выглядит следующим образом:
1.  **Обнаружение несоответствия:** Парсер находится в процедуре, ожидающей токен `X`, но встречает токен `Y`.
2.  **Запись ошибки:** В таблицу ошибок добавляется запись: "Ожидалось `X`, встречено `Y`".
3.  **Пропуск токенов:** Запускается цикл, пропускающий токены.
4.  **Поиск синхронизирующего токена:** Цикл завершается, когда встречается токен из набора `{S1, S2, ...}`, заранее определенного для данной процедуры.
5.  **Продолжение разбора:** Парсер возобновляет анализ с найденного синхронизирующего токена.

### Пример работы
Рассмотрим входной код с несколькими ошибками:

```python
def ca%lc(a: int, b int) -> int:
    return (a + b) * c;
```
Анализатор обработает его следующим образом:
1.  **Лексический анализ:** Лексер обнаружит ошибку в `ca%lc` и создаст три токена: `ca` (id), `%` (ошибка), `lc` (id).
2.  **Синтаксический анализ:**
    *   **Ошибка 1:** В `parse_Start` парсер успешно обрабатывает `def`, а затем `ca`. Но следующий токен — `lc`, а не `(`. Это "разорванный идентификатор". Парсер регистрирует ошибку *"Ошибка в имени функции"*, пропускает `lc` и находит синхронизирующий токен `(`.
    *   **Ошибка 2:** В `parse_Params` парсер разбирает `a: int,` и переходит к `b int`. Он ожидает `:`, но видит `int`. Регистрируется ошибка *"Ожидалось ':' после имени параметра"*. Включается синхронизация (метод `sync_param`), которая пропускает `int` и находит синхронизирующий токен `)`..

Таким образом, метод Айронса, реализованный с учетом контекста, позволяет выявлять несколько независимых синтаксических ошибок за один запуск анализатора, предоставляя пользователю полный отчет о проблемах в коде.
